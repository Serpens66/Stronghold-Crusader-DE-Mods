# Popularity integration

Popularity is part of ExtraFeatures' existing host settings, presets and mode gate.
All imported overrides start inactive; their report-point defaults and bounds are
preserved. No settings or presets are imported from the retired standalone testmod.
Existing ExtraFeatures property identities, defaults and settings storage stay intact.
Fear popularity is independent of the existing unit/combat fear neutralization option.

The maintained generator owns only the Popularity partial model/catalog, its marked
XAML content slot and ExtraFeatures.Popularity locale keys. Other settings and locale
values must remain unchanged. The section participates in the existing topic/search
presentation, with contextual subsection headings and no nested folding sections.

The process-lifetime library/missions path applies snapshots at early initialization,
NativeLoaded and successful start, and releases owned overrides on every matching end.
The shared adapter updates the mode gate first. Only enabled ordinary overrides resolve
engine values. Anonymous stack ownership and failure rollback retain foreign layers.
Fear uses the public APIShared 0.15 SetLevelContributions broker; no new native hook or
report correction is installed. APIShared remains the sole owner of those shared paths.

verify-popularity.ps1 checks the real production view model with the maintained preset
engine and external boundary doubles, old payloads without new fields, persistence,
authority, locks, modes, lifecycle checkpoints and override ownership. Compiled binding
checks use original game/selected SDK signatures and actual item/style DataContexts.
SettingsPresentationTests runs the compiled presentation and actual APIShared catalog.
Test-Package.ps1 exercises real MSBuild copying with equal/newer stale timestamps,
equal-size different content, missing/damaged assets and pre/post-install gates.

The source/package/installation SHA-256 chain includes all evaluated copied Content,
including images, locales, XAML and manifest. DLL identity/version checks use the
published BepInPlugin metadata; ExtraFeatures' existing AssemblyVersion is preserved.
Unrelated installed files and user settings are retained.

These checks do not prove actual Noesis rendering, game effects, save/load or multiplayer
execution. A fresh game run must separately check the Popularity foldout, search/presets,
signed contributions and both fear switches; actual host/client logs are still needed.
The existing unsigned auxiliary religion-counter limitation remains unchanged; negative
religion sums are not claimed to preserve every unrelated statistic. The hash-bound
native audit remains in the workspace Popularity contribution baseline dossier.
