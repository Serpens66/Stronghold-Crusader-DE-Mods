# Native compatibility for Area Construction

Reference native SHA-256 `FBCB93195FC7EFCA9BDAC5204852EFDD76F9818F59A6711750D77C9CEF2831E2`.
Managed reference SHA-256 `BC8B6A395F01D48557DB413600C8DD8D1FDFD3ABDF97BFBBB68A3C56B04FD789`.
Area Construction is disabled on an unsupported native hash. The feature has no pattern fallback because the footprint, cursor scratch, queue and renderer layouts are hash-bound.

## Building and preview contracts

- Managed `EditorDirector` issues mapper placement from its engine-input state. Ordinary placement uses `EngineInterface.PlaceMapperItem` with brush size 0, state 1 and `constructingOnly: false`. Area Construction consumes the primary gesture at `updateLeftMouseStateForEngine` and reissues ordinary inputs after release. The game monitor also serializes the probe.
- Native `DLL_MapAction` at `0x85BD0` enters `0x8AAF0 → 0x90CD0`. The latter reads the active mapper, converts cursor coordinates to the top-left with `scale/2`, and runs `0x77E60` with preview byte 1. Its common placement state is `0x60AD4AC`, copied to cursor state `0x60AD4B0`. `0x60AD45C` is the active mapper and `0x60AD460` the scale. The native disable guard is `0x366A0F8`.
- `0x77E60` runs generic placement checks for the Bakery, Hovel and Mill. In hover mode, the blocked-tile helper `0x7B060` uses mode 2. That path excludes writes to unit records associated with actual placement. Access queries may advance their generation-based search scratch. The Bakery then calls `0x7AA60` for adjacent-road orientation. `0x94120` and the editor brush fallback skip these three mappers.
- `0x5DD70` writes the sprite token to `0x4411FB0 + packedTile*4` and can modify bit 15 at `0x4F64CF0 + packedTile*2` for the one-shot override. Square footprint cells were checked in the candidate-specific valid and blocked branches. `0x41D60` consumes the grid, and its clear at `0x45277`/ `0x4527F` covers rendered cells. Area Construction restores the written footprint after sampling instead of relying on visible-tile clearing. Playable extent is the byte mask at `0x3A11EA4 + y*800+x`. The Extender resolves packed IDs.
- The synthetic hover also scopes cursor scratch `[0x60AD458,0x60AD5A8)`, `[0x3A11DCC,0x3A11DDC)`, `0x3A11E28`, mouse scratch `[0x8EBA93,0x8EBA9C)`, editor owner `0x88E3D78` and mapper return `0x2D4D8C`. It leaves path-search generations intact. `0x60AD59C` must have no one-shot preview override pending.
- Sprite tokens are file in the high word and image minus one in the low word. `0x1A2D90` translates them for `GameMap.processTestMap`. Bakery and Hovel are 4×4 and the Mill is 3×3. The fallback image for a blocked Bakery is workshop frame 417, and for the Mill it is Buildings2 frame 219. For the Hovel the live Extender player appearance selects the base image at `0x2E90A8`. The footprint tile order comes from `0x619C0` and `0x69850`, with native quarter turns 0, 2, 4 and 6.
- Fletcher, Poleturner, Brewer, Blacksmith, Armourer and Tanner also use the Bakery's 4×4 preview and road-orientation contract. Their workshop base images are respectively 1, 577, 865, 1153, 1441 and 1729, with the same open-ground frame offset of 128. These mappers use the ordinary Chore 28 construction and live cost row, with no first-free exception.

## Funds and submission

- Regular clicks check `0xCC420` and enqueue Chore 28 through `0x23990`. `0x12090` decodes X, Y and mapper (signed shorts), scale and variation (bytes), and an extra short, then calls `0x6D580`. That call revalidates before native construction and debit. The active cost row is read through the Extender. `0x3665FC8` is the free-build flag, and native world kind at `0x3665F28` selects editor and special modes. Tutorial step limits and the alternate charging mode use the regular single-placement input.
- The building limit is read at `0x64CCC04` (20 free global slots required before each action). Network mode at `0x8574B90` also checks the per-player count at `0x64CCBB4 + player*4`, with threshold `4000 / max(2, participants) - count >= 2`. The participant records are at `0x8574BCC + player*4` and `0x8574C44 + player*4`.
- The pending queue is at `0x8574320 + 0xB0BF8`, 500 entries of `0x500` bytes. Byte +8 is the opcode, signed byte +9 is the state, sender is Int32 +4 and the body starts at +17. Only state zero and state >=10 can be reused. Network transport adds a 23-byte record to the 1,000,000-byte outbound buffer with cursor at `0xA98690`. Admission allows only space verified under the engine monitor, then throttles large releases over successive director frames.
- Before updating to a new DLL, re-audit each read and the full preview-only and commit branches, including editor and network cases. Confirm the renderer writes fit the restored footprint, and compare the live managed entry points with the real managed assembly.

## Woodcutter and attached storage

- Woodcutter uses the normal 3×3 sprite footprint with Buildings2 frame 1, but takes the specialized proximity branch at 0x7820C in the validator. Emergency eligibility at 0xB9710 checks the owner flag at 0x67E83E8, live wood at 0x379B2A8 + actor × 0x583C, and the live construction cost at 0x67E5BC8. The mod reserves this exemption once per preview or queue projection. The Granary's related exemption reads 0x67E83F1 and uses cost 0x67E5D08.
- Stores, Granary and Armoury use Buildings2 frames 26, 278 and 294 and scales 5, 4 and 4. The selector at 0x780D0 protects enemy proximity and hostile access in networked play. Terminal calls at 0x789D9, 0x78A59 and 0x78AD9 use 0xC72C0 to find an active matching owner and storage type on a cardinal perimeter. Earlier terrain, ownership, occupancy and count rejections remain authoritative. 0xB8140 counts live empty records up to the native allocation watermark. Thresholds are 32/8/8, with four records consumed by one Stores command. The first qualifying segment can take Vanilla's separate start branch.
- The Script Extender already owns the 0xC72C0 detour and exposes `BuildingR3EventHooks.OnIsBuildingAdjacentToOther`. Use its synchronous Post result with a thread-local scope for one matching synthetic hover with a permitted connected draft neighbor. The Extender retains its original call and any veto from the outer placement validator. Neighbor lookup scratch 0x67E8380–0x67E8387 is restored after preview. The hash-bound contracts also cover the three validator CALL instructions, the exact actor/type/scale/coordinates and native mouse state zero.
- Real builds take the unmodified adjacency result, the original mapper command and native placement. Delayed queue receipts are tracked by actor, mapper, and the exact planned cursor derived from the body's corner and footprint size. After a submitted storage command, following candidates are probed against the live map once that exact command has left the pending queue. An unsuccessful command cannot lend provisional adjacency during the commit.

- The optional host rule removes the empty-record family caps at the native `0xB8140` count query. ## Quarry block and pile construction

- `0x6D580` dispatches quarry construction to `0x76780`. The latter registers the 6×6 main footprint before searching for the optional 2×2 pile. Unlike the main preview, the pile is described by its top-left corner. Vanilla calls the dedicated resolver at `0xBD7A0`, which generates perimeter positions via `0xC0270`, validates each via `0x77E60`, and compares its path component to the quarry origin. The constructor sets `IsBuilding` (0x400) on the four pile cells and stores the actual pile ID on the quarry.
- Before each committed site, APIShared `PathComponentRefresh` mirrors the constructor's dirty-component check at `0x60AD660` and calls `0xE49D0` when required. APIShared `QuarryPilePlacement` owns the native pile queries and the scoped filter through the Script Extender's placement event.
- The block preview protects the full planned extent and its one-tile outer strip. The build path rescans allowed positions immediately before each construction and scopes pile validation to that one construction only. Single clicks use the ordinary native command. Bugfixes and QoL's human rotation and AI Keep-facing automation retain their own placement paths and consume the normal quarry–pile relationship.
- Multiplayer quarry blocks use an authenticated APIShared Chore with preview-approved positions and the full protected block. A peer readiness proof and acknowledgement precede submission. The receiver gets its actor from the authenticated native issuer and reruns per-site validation and construction in deterministic block order. Other mapper actions use their existing transport. The quarry channel and readiness processing continue on peers with local area construction disabled.
