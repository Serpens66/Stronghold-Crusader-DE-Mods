# QueueTest native contract

Reference binary: `CrusaderDE.dll` SHA-256 `FBCB93195FC7EFCA9BDAC5204852EFDD76F9818F59A6711750D77C9CEF2831E2`.

`FUN_18011C3A0` occupies RVA `0x11C3A0` through `0x11C3E6` inclusive (71 bytes). Its only caller is the unpack side of Vanilla Chore 71 at RVA `0x176C0`.

Windows x64 parameters are RCX = tribe-manager array base, EDX = one-based tribe game ID, R8W = tile X, R9W = tile Y, `[rsp+0x28]` = waypoint index, and `[rsp+0x30]` = 16-bit move mode. Chore 71 serializes this game ID unchanged. The replacement is a whole-function managed detour. It either returns without native writes after QueueTest has captured the waypoint, or calls the generated trampoline with every argument unchanged.

The original body computes `tribeOffset = tribeId * 0x688`, writes the coordinate pair at `manager + tribeOffset + 0x5B4 + waypointIndex * 4`, writes `waypointIndex + 1` at `manager + tribeOffset + 0x5DE`, and writes the move mode at `manager + tribeOffset + 0x582`. It returns directly and has no nonvolatile-register or flag contract beyond the Windows x64 ABI. The detour library relocates the overwritten entry instructions into its trampoline; QueueTest does not branch into the middle of the function.

In non-networked modes, QueueTest creates its managed state on the first local selected Shift Move, whether the Script Extender move event or Chore 71 arrives first. The first observer enqueues the Move and records the opposite signal as an expected duplicate; the second observer consumes that signal without adding another command. QueueTest returns from the helper before Vanilla can write the managed Move into its ten-point buffer. Existing native movement remains an unchanged predecessor, while every Shift Move after it shares the 128-command FIFO and nine-slot visual pages with target commands. Creating a state from Chore 71 requires Shift and local selection; an already matching state also consumes a delayed expected Chore after Shift has been released. Internal dispatches and Chores for foreign or AI tribes without a matching state always use the unchanged trampoline.

## Multiplayer Chore synchronization

The runtime Chore-handler table begins at RVA `0x2C7A30` and contains eight-byte function pointers indexed by opcode. After the Script Extender has initialized it, QueueTest verifies entries 17, 36 and 71 against the following exact handlers before enabling multiplayer queue capture:

- Chore 17, first Move: handler RVA `0x10AE0`, 470 bytes, exclusive end RVA `0x10CB6`.
- Chore 36, target order: handler RVA `0x12BF0`, 450 bytes, exclusive end RVA `0x12DB2`.
- Chore 71, Shift waypoint append: handler RVA `0x176C0`, 487 bytes, exclusive end RVA `0x178A7`.

The Chore 17 and 36 hooks replace their complete handler functions and have ABI `void(void)`: parameters are exchanged through native globals, not registers or caller stack arguments. Both hooks call their generated trampoline exactly once and restore every temporarily changed global in `finally`. QueueTest verifies unique entry signatures, exact function sizes, tails and RET boundaries for the reference hash. Chore 71 remains intercepted at its sole append-helper call, whose explicit ABI is documented above.

RVA `0x85F8FEC` is the Chore mode (`1` packs an outgoing command; `0` unpacks and executes it). The shared payload globals used here are tribe ID at RVA `0x86C132C`, Chore-36 command or Chore-17 tile X at RVA `0x86C1330`, and Chore-17 move type at RVA `0x86C133C`. QueueTest only changes payload globals while mode 1 is synchronously serializing a local player command in a real multiplayer session.

The sole Chore-17 producer emits move-type bytes `0`, `1` or `0x81`. Bit `0x80` already has Vanilla meaning and the unpack thunk removes it before invoking the move-order function; bit `0x40` is otherwise unused and reaches the Script Extender pre-event. QueueTest therefore serializes queued variants as `0x40`, `0x41` or `0xC1`, which all execute as marked event values `0x40` or `0x41`; clearing `0x40` restores move type `0` or `1`. No other producer value is marked or accepted. Chore 36 uses commands `0..38`; QueueTest adds bit `0x80` only to supported commands `AttackUnit` (4), `AttackBuilding` (9) and `ForceAttackBuilding` (36), then removes it before storing the command.

Only the sender uses Shift state, local player ID and local selection, and only to decide whether an outgoing mode-1 payload receives a marker. No queue state is changed at that point. During tick-synchronous mode-0 execution, every peer consumes marked Chores 17 and 36 in the same Script Extender pre-event, restores the original parameter, enqueues it and skips Vanilla execution. Chore 71 already unambiguously denotes a synchronized Shift waypoint, so every peer captures it at the append helper without an extra marker. Unmarked Chores 17 and 36 remain Vanilla commands and deterministically discard any managed queue for their tribe.

Queue identity is unit-stable. Every member is stored as a one-based Unit ID plus Global ID and maps directly to one queue cohort; a cohort stores owner, immutable command references, independent execution progress and stable visual pages. A tribe ID plus tribe Global ID is only the cohort's current dispatch vessel. Selection changes and Vanilla regrouping therefore cannot transfer or discard a queue. Dead, missing or reused unit slots are removed individually.

During every synchronized mode-0 command, QueueTest enumerates the living members of the Chore's current tribe and applies the command to their existing cohorts. Previously unqueued members form a new cohort behind their current Vanilla predecessor. Existing different queues are never merged merely because the units share a tribe. Capacity is checked for every affected cohort before any enqueue, so a group append is atomic. An unmarked normal order removes only the identities currently contained in its tribe.

Before dispatch, cohort membership is partitioned by the units' current synchronized tribe IDs. Every resulting branch gets independent mutable progress while retaining the same immutable command objects and stable visual slots. Branches are processed by owner, smallest Unit ID, smallest Global ID and cohort ID. Two branches sharing a physical tribe coalesce only when their complete command, predecessor, progress and visual state match. Otherwise QueueTest separates one branch immediately before its next dispatch. Managed dispatch calls the Script Extender's direct native order implementations while the recursion guard is active; it does not create another Chore. If either additional handler signature, runtime table entry or detour fails validation, both multiplayer marker hooks remain disabled/rolled back and Chore 71 uses Vanilla unchanged. This does not disable the existing singleplayer or editor queue paths.

## Unit removal and deterministic tribe isolation

`FUN_180123EA0` occupies RVA `0x123EA0` through `0x123FD7` inclusive (312 bytes); RVA `0x123FD8` is padding. Its Windows x64 ABI is `void(GameTribeManager* manager, int unitId, int tribeId)`, with RCX = manager, EDX = one-based Unit game ID and R8D = one-based Tribe game ID. The function removes the member bit, decrements the tribe member count, clears the Unit's tribe fields when they still identify that tribe, repairs a removed leader and updates the tribe. QueueTest calls the original function directly and does not patch it. Startup verifies its unique entry signature, exact RVA, function size, tail jump and boundary against the reference hash.

Script Extender 1.42.0 exposes `UnassignUnit(tribeId, unitId)` but forwards its two integer arguments to this native contract in the contradictory order. QueueTest therefore does not use that wrapper. To isolate a cohort, it creates an empty tribe through the Script Extender, copies owner and combat stance, removes and assigns members in ascending Unit-ID order, verifies every Unit ID plus Global ID after assignment, and then reissues the active command. Creation or assignment failure retains the queue; any partial move is deterministically rolled back to the source tribe and the empty destination is marked for safe deletion.

RVA `0x11B520` initializes a new movement path, including the packed index/count dword at manager-relative offsets `0x5DC/0x5DE`. A public `GameTribe*` begins at `manager + tribeId * 0x688 + 0x2A`, so QueueTest reads the same fields at `GameTribe` offsets `0x5B2/0x5B4`. The count is the fixed number of stored points and is not a remaining-count or completion flag.

Vanilla's read-only predicate at RVA `0x1178D0` returns 1 only when every living member of the tribe satisfies the native movement-arrival check. QueueTest calls this same predicate and also requires the movement mode at manager-relative `0x582` (`GameTribe + 0x558`) to be zero. A finite Shift waypoint chain uses mode `-1`; Vanilla resets it to zero only after reaching the final point. This combination distinguishes final completion from arrival at an intermediate waypoint and from a still-active patrol. QueueTest never writes this native movement state.

`FUN_1801222A0` at RVA `0x1222A0` is the 1371-byte tribe overlay renderer. Its ABI is `void(GameTribeManager* manager, int tribeId)`, with the Windows x64 arguments in RCX and EDX. QueueTest verifies a unique 48-byte entry signature before adding its whole-function detour to the same fail-closed transaction as the waypoint hook.

Vanilla draws movement markers only when manager-relative patrol mode `+0x582` is nonzero. During renderer trampoline calls only, QueueTest substitutes each outstanding stable visual page in FIFO order as a separate `PatrolOnce` view of up to nine Move or attack slots. The current page is submitted first and retains Vanilla's numbers `1` through `9`; later pages retain their flags but QueueTest's optional draw filter suppresses their page-local number sprites. This shows every outstanding destination without presenting repeated numbers as global ordinals and prioritizes current-page markers if Vanilla's fixed draw list approaches capacity.

Overlay lookup follows the selected tribe to every distinct unit cohort currently represented in it. Each cohort is rendered once in deterministic order; split branches retain their pages and ordinals, while physically grouped units with different queues show each distinct path. Equal branches are coalesced before rendering, and Vanilla's draw submission helper deduplicates equal marker submissions on the same tile.

Each managed command receives its page and ordinal at enqueue time and remains visible while pending or active. Completion, invalidation or a failed dispatch hides that slot without renumbering later slots. Hidden history preserves the number positions on the current page but its flag and number submissions are filtered out. When every slot on a page is complete, the next page becomes current and its stable numbers become visible; completed earlier pages and their command lookups are then discarded to keep long-running queues bounded. Unit targets are resolved to their current tile on every render; building targets use their beginning tile. The validated target-marker address from that same lookup is reused after the overlay submission, so attack entries retain both their projected target icon and their movement-target flag without a second manager lookup.

When the managed queue is created behind an existing Vanilla movement chain, its stored points 1 through count-minus-one become the first visual slots. Points below the native current-waypoint index are initially hidden, the current and future points remain visible, and managed commands continue at the next ordinal. Once native movement completes, all of its slots are hidden but remain projected as placeholders until the page changes or the queue ends. Stale native point buffers with movement mode zero are not imported.

QueueTest saves and restores the original mode, current index, 16-bit point count, and all ten coordinate pairs in a `finally` block. Script Extender 1.42.0 incorrectly declares the point count as `UInt32`; QueueTest therefore accesses the proven `ushort` at `GameTribe + 0x5B4` directly and never touches the adjacent word. The trampoline receives the original manager pointer and one-based tribe ID unchanged, and no simulated tick can observe or execute this transient visual projection.

`FUN_1800417A0` at RVA `0x417A0` is the 232-byte overlay draw-submission helper. Its Windows x64 ABI is `void(void* drawManager, int category, int spriteId, int layer, int verticalOffset, int tileId, int flags)`: RCX, EDX, R8D and R9D contain the first four parameters; the remaining three are at `[rsp+0x28]`, `[rsp+0x30]` and `[rsp+0x38]`. QueueTest verifies its complete body, unique 48-byte entry signature and RET boundary before installing an optional whole-function detour. Only while nested inside QueueTest's tribe-overlay trampoline does that detour count calls matching Vanilla's exact `PatrolOnce` flag tuple (`category=0xAC`, `layer=0x12`, `verticalOffset=-1`, `flags=0xA0022`, `spriteId=0x138..0x141`). Flags for visible Move and attack entries pass unchanged; flags for hidden history slots are suppressed. The corresponding number sprites use the same tuple with `spriteId=0x12E..0x136`; visible numbers pass only for the current page, while hidden-slot and future-page numbers are suppressed. Every unrelated draw submission uses the unchanged trampoline. Failure to install this optional filter cannot disable command queuing or execution, but hidden history and repeated page-local numbers can then remain visible as Vanilla markers.

The helper stores at most 250 draw records. QueueTest therefore does not attempt multi-digit or globally increasing numbers: the current page contributes at most nine flags and nine numbers, and later pages contribute flags only. With the managed queue limit this adds at most 128 visible destination flags plus nine numbers. The existing helper also deduplicates equal category/sprite pairs on the same tile, so drawing a second identical digit at the same anchor cannot form a multi-digit number; true `10..128` labels require a separately proven render path with horizontal placement.

Vanilla marks the target of a selected unit attack by writing `1` to the 16-bit word at public `GameUnit* + 0x68`; the Unit renderer consumes and clears that word. The native references place it `0x2C` bytes before the Unit Global ID at `+0x94`, with `sizeof(GameUnit) == 0x490`. Building attacks analogously use the 16-bit word at public `GameBuilding* + 0xC2`, `0x16` bytes before the Building Global ID at `+0xD8`, with `sizeof(GameBuilding) == 0x32C`. QueueTest writes these marker words only after revalidating the one-based target ID, Global ID, alive state and positive health. Building Attack and Force Attack share the building marker path. A marker-layout mismatch disables only these attack-icon writes; the command queue and multi-page flag projection remain active.

The Script Extender 1.42.0 `GameTribe` field names at these offsets are not used because their current semantic labels conflict with the native data flow. Likewise, `OnTribeGetNextPatrolWaypoint` is not used: its hook derives a zero-based span index but exposes it as `TribeId`.

The same queue and dispatch model remains enabled for skirmish, campaign/trail, multiplayer and map-editor sessions. `Shared/GameModeHelper.cs` distinguishes real multiplayer from local modes; only real multiplayer uses the Chore-marker path. Local selection participates only in marking the outgoing mode-1 Chore; cohort membership, branching, tribe creation and dispatch derive solely from mode-0 simulation state and stable sorting. Successful native initialization enables command capture immediately. `OnStartMap`, load and unload events clear stale queue state but never gate or disable capture, because an editor session can become interactive without raising `OnStartMap` after plugin subscription. `NetworkMode: 1` requires matching QueueTest installations in multiplayer. No Chore 106 command, MessagePack registration, MPTest dependency or second network packet is used: the original Vanilla Chore retains its command ID, scheduled tick and ordering.

Queue state is intentionally process- and map-local. It is never serialized, restored from a save, or migrated from an older QueueTest implementation; map load, unload and restart discard it completely.
