## Runtime native access

The read-only wall availability getter is RVA `0xCF640`, `int(playerManager*, int playerId, int goodsId)`. Its entire 179-byte reference body is stored in `NativeAvailability.ReferenceCode`; SHA-256 F2C875634DF70ABE13AE3938E6F63B1C4BCF2E61061B753BCD3FB9EFFF23B21A. Pointer and one-based player ID are validated through public SE methods; goods ID uses `eGoods.STORED_STONE_BLOCKS` (4, checked against the installed enum). The delegate is retained by the static process runtime.

Resolution: first validate the reference RVA against live bytes. On mismatch, attempt the exact full-body pattern exclusively in executable PE sections of the SE snapshot, require uniqueness and revalidate live bytes. Since the body contains relative globals, an equal byte body at a different RVA is not accepted without a new semantic audit. Unknown DLL hashes, ambiguous/missing patterns, changed live bytes or invalid module bounds leave the entire test feature inactive. The hash gate runs before this address is used. The quota getter itself is not patched.

This getter preserves Vanilla's campaign/cheat result 100, native mode-6 resource branch, stone-times-two-minus-remainder branch and clamp to 250. The consumer does not interpret modes or calculate prices. In `0x6F230`, resource exhaustion is `available < alreadyPlaced`; the public command maximum independently counts raster visits. `WallPolicy.Predict` therefore limits new tiles to the exact getter result plus one, while `Raster` honors the original command maximum. The repeated endpoint cannot create a second tile. Re-audit both comparisons after updates.

## Approved permanent graphics hook

RVA 0x5C2D0, full body 237 bytes, ABI `int(tileManager*, int tileId, int rowY, int direction)`. Native return is 0/1 in EAX. Only call sites are 0x65DD6 (direction 0) and 0x65E4F (direction 2), both inside 0x65830. The helper reads four cardinal neighbor masks through the native row-delta table. Its positive result selects the orientation/rotation-aware low/high straight sprite family in Vanilla; its negative fallback normally writes a special sprite and ORs high.

Backend is the installed RedBird.Backends.NativeX64 SHA-256 0843DD4C381A3E77DD6D8B51D5CCF95465B3FB49BFDF2980F39A212D774AADB0. Only `Absolute`, no thunk following/call following/chaining, scan limit 237. Fourteen required patch bytes round to fifteen: `mov [rsp+8],rbx; mov [rsp+10h],rsi; mov [rsp+18h],rdi`. No branches, relative operands or flag dependencies are displaced. Continuation 0x5C2DF starts the original XOR. Full executable-section scan finds no incoming direct edge into the displaced interior. Installed patch is FF25/disp32=0, inline callback pointer, one NOP; PointerSlot must be zero. Real copied-code tests execute the trampoline and production disabled wrapper for every cardinal neighbor mask.

The callback calls the original exactly once, preserves positive results, and only returns an additional positive result for a published, still-low, intact, owner/row-matching endpoint with exactly one unchanged cardinal neighbor on the requested axis. Public SE spans are reacquired per call; no native-memory view crosses a lifecycle transition. Immutable snapshots are published by the logical runtime, not generated from render timing. Rendering never writes flags, paths, owners or heights. Session retirement publishes an empty snapshot; no installed hook is disposed or repatched. Only a failed prepared candidate may be released. Failed registration cannot activate the session runtime.

## Permanent Vanilla preview validator (2026-10-23)

The same reference native hash admits RVA `0x7A3B0`, full 1627-byte body, ABI `void(tileManager*, int playerId, uint beginX, uint beginY, uint endX, uint endY, short mapper)`. Only direct callers are `0x6F299` (synchronized execution) and `0x941F1` (interactive wall UI). Automatic AI placement uses `0x77CF0` instead. Domain mapper is the checked `eMappers.MAPPER_CRENAL` symbol.

The validator resets the int invalid status at manager+`0x204E6E4` to 1 and clears it only for a fully valid Vanilla line. Its independent second proof is UI global `0x60AD494` = public tile manager base `0x405EDB0` + that offset. `0x61210` reads it to select invalid crenel preview sprite `0x60014` versus valid `0x60004`, then zeroes invalid preview cost count; `0x94120` reads the same status on release before enqueueing Chore 25. No fabricated error-reason field is written. Bounds, terrain, missing supporting normal walls and other Vanilla checks run first and remain authoritative.

Only the installed, hash-verified NativeX64 Absolute backend is admitted. Fourteen patch bytes displace 18 complete bytes: `mov [rsp+10h],edx` (4), `push rbx` (1), `push rbp` (1), `push rdi` (1), `push r12` (2), `push r13` (2), `sub rsp,80h` (7). The trampoline continues at `0x7A3C2`. The audit checks all direct executable-section edges, finding no entry into the displaced interior. No RIP-relative operands or branches are displaced. Register/stack effects are replayed by the original trampoline; the production seven-argument callback and stack unwind are executed by the backend fixture with an isolated native ABI probe after this exact prologue. The probe does not execute the real game's global-dependent validator body.

Installation checks the complete load-time snapshot and live body before claiming Exclusive [7A3B0,7A3C2) and Observe [7A3C2,7AA0B) through the existing public NativeSiteRegistry. A failed unpublished candidate alone may dispose/unregister. From the first Enable attempt onward the owner remains rooted and registered permanently, with errors logically disabling the callback. A refused/unknown preview contract leaves existing execution protection active. The native hash gate and relative globals intentionally prevent accepting a moved function by a byte-pattern match; unknown hashes need a fresh semantic/layout audit, not a fallback to the old data offset.

The callback calls Vanilla exactly once. A mod veto can only change zero to one in that data int. Current-thread OnBuildWall scopes bypass the additional policy evaluation: execution always uses fresh command inputs, never preview cache state. Interactive checks reuse WallAdmission and use CF640's quota as the maximum that 94120 would queue, keeping visit count distinct from actual-placement quota. One cached request is reused only after every raw cell read (including failed/empty reads), relevant saved preference, owner, coordinates and quota matches. Session retirement clears it. No simulation state, saved assignment or resource is changed by prediction.

NativeSiteRegistry was added in APIShared commit 5ed595c while its declared version was 0.9.1; no newer minimum is introduced merely for the current 0.14.0 SDK. Consumer compilation tests the exact public registry members and rejects missing members, while unrelated additions/version changes remain accepted. No APIShared code, package or README is changed.
