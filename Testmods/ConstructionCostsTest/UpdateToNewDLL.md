# Native contract used by the construction acceptance fixture

`Fixture.FreeBuild.cs` only reads native Undo eligibility fields. It installs no hook and performs no raw native-memory writes. Cost and resource setup use the existing public APIs; construction and Undo use the genuine game paths.

- Feature: `costs-freebuild-undo`, checking that the genuine FreeBuild menu and map loader naturally enter the mode required by construction Undo.
- Reference SHA-256: `FBCB93195FC7EFCA9BDAC5204852EFDD76F9818F59A6711750D77C9CEF2831E2` (canonical installed `CrusaderDE.dll`).
- Data RVAs (signed Int32): native world kind `0x3665F28`, native mode `0x8574B90`, decoded Chore actor `0x88E3D6C`, and native viewed actor `0x88E3D70`. Managed `GameData.mapType` and `PlayState.game_type` do not substitute for these native guards.
- Semantic derivation: the full Chore69 consumer `0x172B0` records decoration history through `0x72820` only in native mode zero and when the decoded actor equals the native view. The history writers `0x72820`/`0x727E0` and validator `0x7B7F0` reject native world kind 3 unless mode is 99. `0x81870`/Undo rejects the spectator flag. Chore75's `0x17B10` consumes recorded object slots; it is not proof that a given UI mode can produce history. No projectile-type-10 restriction exists in the mode-zero recording branch: the type10..13/15 checks belong to the other branch's decoration limits.
- Address source: the loaded Extender `CrusaderLibrary.LibraryModuleHandle`, read by reflection because the genuine field is internal, plus one of the private `UndoNativeField` identities. The module field must retain the exact `IntPtr` contract and the module must be nonzero.
- Image validation: require `ConstructionCosts.IsAvailable`; that API validates the exact loaded native SHA-256 before exposing its table. Additionally require its internal constant `NativeHash` to equal this fixture's explicit reference hash before touching the data address.
- Search region/fallback: no scanning and no fallback. This optional acceptance-only reader intentionally fails closed on a changed SDK hash contract, unavailable validated tables, or changed module-handle contract. A pattern matching a caller alone would not establish the data-global semantics.
- Update procedure: re-audit the full native Undo producer/dispatcher, its game-type/mode/pause guards, the mode-global writers, and the Chore75 consumers. Verify the canonical native hash, re-derive the data operand in native disassembly, independently confirm it against other readers, and update the fixture's hash/RVA together. Recheck the genuine Extender module field. Run the genuine FreeBuild scenario; a zero mode alone is not proof of successful Undo.

The fixture logs exact native guards, managed `undoAvailable`/`spectatorMode`, object generation/type/owner/state and receipt count before Undo and after four real ticks. Native world kind 3 with mode other than99 is classified as unsupported rather than reported as a transaction-adapter failure. If the native mode supports Undo, actual Chore69/42 construction is followed by public `HUD_Main.UndoLastAction`; accepted resource changes are witnessed through existing R3 events inside authenticated production Chore75. Object removal and receipt consumption are checked separately in the diagnostic snapshot, then required together by the acceptance condition.
