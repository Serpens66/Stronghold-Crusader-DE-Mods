# Pathfinding surface acceptance

Explicit-request-only disposable local mission test (Skirmish or the named save fixture). Uses public APIShared Automation and SimulationTickEvents plus the existing Script Extender movement observer. No native hooks, OS mouse/keyboard input or save writes.

Build with `build.bat` (build only). Run `Run.ps1 -SdkRoot <prepared APIShared checkout/package root> -OutputDirectory <outside-game evidence directory> -PathfindingPackage <built Pathfinding_Serp package>` only after coordinating game access. Both APIShared plugin and bootstrap must come from that SDK. The wrapper temporarily tests Script Extender, optional installed Fixes, selected Pathfinding and this fixture; the canonical runner restores the installation/settings and verifies rollback.

The default local map is `test AI.map`; override `[Fixture] Map` in `BepInEx/config/PathfindingSurfaceTest_Serp.cfg` if needed. The candidate terrain must supply a vacant, flat39x33 region within the human keep's legal wall range. An unsuitable map fails setup and cannot produce a gameplay PASS.

Scenarios:

- `natural-route-corridor`: loads the existing `test_diagonal.sav` through public Automation with current host core/single options, then verifies the actual frozen mission options. Newly spawned spearmen receive an individual quarry-window order (355,332 → 444,368; 89 steps; maximum line deviation 4 tiles) and a group leg (299,363 → 500,367; 201 steps; deviation 12 tiles). Both require fresh Post publication, accelerated-publisher counters, the full public packed path, every directed edge, dry profile-compatible surfaces, the exact owned/requested endpoint and actual arrival. These fixture-specific bounds distinguish the captured 0.1.11 detours (about 28/55 tiles); they are not a bound for arbitrary obstacles.
  An original spectator save obtains temporary control of player 7 through public `PlayerPerspectiveAPI` after registering before load. Both the input-control identity and public local-player identity must confirm player 7; changed control fails before spawning a test actor. Stop clears only the fixture's acquired input control. The API's shared process-lifetime registration is not unpatched.
  Both newly created spearmen are captured through public `IAiMilitaryCapability.TryBeginSpawnScope` with `AiMilitaryRole.None`, protecting just these test actors from automatic military AI collection. Scope completion and disposal run under the engine monitor; a queued result is not acceptance. The fixture waits for the exact actor's public `Applied` result, validates its protected private group's owner/global identity, live state, exact membership and unit back-link, and rechecks before issuing either order. The individual test still calls `MoveToTile`; the group test uses the provided group. No player-wide AI pause or farmer assignment is performed. Public capability/assignment failure explicitly fails setup. A normal human owner needs no AI exclusion and can create its test group through public `Create`/`AssignUnit`. The test does not depend on background UI selection gestures. Short phase logs identify actor initialization, applied protection, mask readiness, tribe confirmation and command publication.
  Before natural-worker acceptance, public mission-scoped `AttackTargetRules` publish seven bidirectional `Always` exclusions between the reproducer's player 7 and players 1–8 other than 7. Native API availability and successful publication are required, followed by 256 simulation ticks for existing projectiles before the farm or test actors are spawned. This is the shared unit-target exclusion used by Diplomacy, not an alliance or topology change and not a universal damage veto. The fixture does not install Diplomacy, edit HP, intercept damage, heal units or change farmer AI. Stop clears its rules; the API also retires them at the world boundary. A death still fails and logs actual HP/max/AliveState/projectile-death-marker/type/AI/position.
  Only **after natural-worker acceptance**, the disposable loaded mission removes existing troops, engineering support and war machines through public `DeleteUnitSafe`, using the frozen SDK `AiMilitaryCatalog.IsMilitary` classification. Lords are explicitly excluded first; farmers, other civilians, neutral animals and ordinary buildings are retained. Every deletion rechecks ID/global/type/owner and confirms the normal deletion marker; initial receipts must retire through native cleanup, followed by another 256 projectile-settling ticks. The existing native tick observer removes new military every 64 ticks during the forced Spearman cases, always excluding the exact current fixture ID/global identities. Counts by category/type and retained Lords/civilians/fixture identities are logged. Stop disables this fixture-only cleanup. No save is written and no global unit defaults, AI linkage or HP/damage fallback is used. This cleanup intentionally changes only the subsequent combat-free arrival test; the natural farmer case runs beforehand in its original army/structure context.
  Natural routes decode from the captured Pre movement start: Current only for flags 0 and substep 8, otherwise Next2. Stored Previous coordinates are diagnostic only, because Vanilla can write Current there while already stepping from Next2. Pre/Post movement snapshots and a failing directed edge's index/from/to/direction are logged. The complete route must still use valid first and subsequent edges and end at the unit-owned target matching the correlated Pre request.
  The natural FarmerCattle and 201-step Spearman fixtures confirm their live public `Default` profile, which resolves to `Any`: legal keep, stockpile and stair surfaces are allowed. Bounds, native tile validity, directed edges, dry tiles and the exact endpoint remain independently checked; the first permitted raised tile is logged with index/coordinates/flags. A modified Large profile fails these fixtures explicitly rather than assuming its whitelist permissions. The 89-step individual window retains its stricter flat-ground assertion. Fixed spawn sites log bounds, generic walkability, chimp/building IDs, flags, height, native outgoing edges and profile. A transient chimp occupant is allowed up to 512 normal simulation ticks to leave; the vacant-site check and exact spawn share one engine lock. The fixed 201-step start is never moved and no foreign actor or terrain is removed. Normal farm placement tries (500,370) first and then symmetric 10/20-tile rings, without bypassing placement or relaxing job/route comparisons.
  A separate step arms the existing Pre/Post observer and places one dairy farm through normal public placement for the reproducer's player 7, east of the quarry corridor (480–520,350–390). Forced spearmen keep the local player's ownership. The test never commands a farmer or writes AI/job links. Natural proof requires a real FarmerCattle job route after arming, stable unit/global identity, correlated accelerated publication, a complete unconsumed valid path crossing the fixture, and a native production link to the newly created farm. Global line deviation is reported only: the required castle exit can legitimately produce about 38 tiles of deviation. The hard 12-tile bound instead applies to the complete contiguous +X leg after that exit, including its actual start and end, spanning x355–444. A comparable leg starts in the observed exit region x290–325/y350–380 and ends east of x444 at y350–390; a different exit/job is not accepted as reproducing this comparison. The unit must not have been a player-7 dairy farmer immediately after loading: normal employment of an existing peasant qualifies as a new occupation. Whether its global ID is also entirely new since loading is logged separately as `birthNewGlobal`; new employment does not claim a newborn unit. Existing loaded farmers receiving new routes are logged separately. Missing legal farm placement, new recruitment or a qualifying fresh natural route explicitly fails this step; the forced spearmen cannot establish natural-worker acceptance. The disposable loaded mission is never saved.

- `ground-route-shape`: starts a disposable Skirmish, verifies an empty flat 50x27 region, and issues newly created 45/22 move orders individually and through a one-member group. Reads the actual published route through the public Extender path-plan API before consumption: 45 steps, existing directed edges, exact requested/unit-owned endpoint, cross-product distance at most 45 from the direct line and at most 15 direction changes (the former raster had 44). Requires actual accelerated-publication counters and subsequent arrival. It does not repair old saved routes, use OS input or create a wall.

- `surface-matrix`: fast individual searches enabled; four mounted types and a spearman exercise regular replans while walking; a mixed group follows; a closed ring then checks mounted rejection and successful foot travel.
- `surface-groups-no-singles`: same mixed-group and closed-ring checks with individual acceleration disabled before mission start.

The fixture builds a normal high wall with opposing normal stairs, verifies actual tile flags and independently searches the native direction grid. It requires the unrestricted shortest route to use real structures and the mounted ground route to be longer. Closing the other three wall sides must retain a foot route while eliminating the ground route. It then inspects real published unit paths, all simulation ticks, identities and arrival/rejection outcomes. Setup failures, absent fast-route counter changes and missing expected transitions are failures.

The first game attempt failed setup because the complete wall was absent; it did not exercise or accept gameplay. The revised fixture provisions and verifies actual Stone, accepts only a complete wall, and records native placement status immediately after each normal call. A successful compile is not gameplay acceptance. It does not prove real multiplayer or repair pre-existing saved routes.
