# MoatMove Fast rewrite

Version remains 0.1.0. The original BugfixesAndQoL implementation is not modified by this work. Precise retains its optimized weighted planner and publication behavior. FastMoatBridge.cs was removed, including its undirected graph, finite search rejection and single expiring local-player permit.

Installed CrusaderDE.dll SHA-256: FBCB93195FC7EFCA9BDAC5204852EFDD76F9818F59A6711750D77C9CEF2831E2. CURRENT.json, database manifest and function records were matched against it. Script Extender target is 2.5.0, canonical source commit 5f02af6d074af7c741ebdaaccb48add39eba1bf4. Native names remain candidate where the semantic baseline labels them so; the contracts below were checked through actual dataflow and installed instruction bytes, rather than inferred from names.

The complete movement audit is retained under ../../_inspect/MoatMove/NativeAudit. E2610 is a confirmed Extender binding: positive next-component results may include the blocked second phase and are not unconditional ground reachability proofs. Native scratch flood stamps cannot invalidate the new Fast fields by themselves. The accepted Precise traversal predicate, including its diagonal convention, remains authoritative for this test mod.

The deferred-command extension follows 8C5F0 input through 195E30, Chore17/10AE0 and 196100, as well as Chore36/12BF0/199C70/11E960 and Shift input through 196CF0/Chore71/176C0/11C3A0. 196100 is a real function entry before command-state mutation; replay preserves all six Win64 arguments and signed movement-flag bits. 199C70 is a 12-byte tail wrapper and is not detoured. 117BC0 only identifies a living, unmounted moat-standing member; zero is not failed ground reachability.

Fast-only entry spans (minimum 14 bytes rounded to instructions): 196100..19610E (14), 12BF0..12C06 (22), 11C3A0..11C3AF (15). The exact signatures are checked before installation. RIP-relative addressing and full entry boundaries are covered by the installed RedBird and native inventory checks. No new inline patch or scratch-register convention is introduced.

Grouping uses public Create/AssignUnit/UnassignUnit APIs. The audit includes 119C00, 11D370, 123EA0, 11A2B0, 119F90 and 11E820. Game IDs remain one-based; group membership bits use gameId/16 and gameId%16. Assignment writes the unit leader, tribe ID, ordinal (GameUnit+2D6) and group Global-ID (GameUnit+2E0); failed grouping restores these additional fields, not merely the tribe ID. Failure keeps the pending command. Existing native queues are carried over when a waypoint cohort needs a separate group: 11C3A0 writes 16-bit coordinates at tribe-manager+tribeId*688+5B4, count at+5DE and mode at+582. 11A980 consumes signed 16-bit current index+5DC and timer+56, tests arrival through1178D0/188340, then calls11B520 with new-order=0. The wider managed count view is not used for this transfer.

Simulation processing subscribes to the existing Extender OnTick path, audited through D1AD0/D1D4F and FrameProvider pause handling. Save callbacks use ModSaveDataAPI binary payloads. The installed archive reader invokes load handling on both Pre and Post; pending bytes are staged and imported once on a subsequent tick after successful Post. Nested unloads clear search buffers without discarding the active load mailbox. New-map/unload outside save loading clears it. Saving a just-loaded paused game retains staged commands even before its first tick. Empty pending sets also produce a nonempty versioned record.

## Fast implementation

- Reverse, directed, unweighted FastRouteField; multiple starts share one target field. Pending, Found, NoRoute, TooLong, Cancelled and invalid queries remain separate. Exhausting a slice preserves the frontier. Packed output is low nibble first and limited to 2,000 directions.
- Ground alternatives take precedence. Proven ordinary ground cases remain native; ambiguous cases use a shared ground field before the friendly-moat field. No old Fast or weighted Precise search fallback exists.
- Normal human move commands wait before196100 while the old native command continues. Each simulation tick allows 8,192 expansions in slices of at most1,024. AI, attack, work and active queue/patrol legs remain synchronous.
- Pending ownership is per game-ID/global-ID pair. New explicit orders replace only matching members; Shift appends retain their original native slot/index/mode and wait behind predecessors. Slot-limit overwrites are coalesced per member. Neither elapsed real time nor cursor activity releases or cancels a pending command.
- Pure groups use one anchor and deterministic local radius-eight distribution. Ground slots have ground-only connections in both directions to their ground anchor; moat anchors distribute onto moat slots. Slots may be shared. Identity-bound distributions remain available to native builders that run after group dispatch. Attacks and work retain exact endpoints.
- Simulated searches use pooled buffers, with a 64MiB budget including the forward attack-candidate field. Active leases cannot be evicted. Two pool slots remain available for synchronous nested queries when four asynchronous commands each own two fields. Cursor states are separate. Topology caches compare actual directed edges and access fields; only changed dependencies restart a field, retaining command ownership.
- Completed paths are live-audited against identity, native start/next tile, target, real unit buffer, capacity and all transitions. Direct publication also restores the required native mode and route variant before the consumer resumes.

Configuration remains `[Movement] Mode = precise` or `fast`, effective after restart. All multiplayer peers must use the same mode. Installation preserves existing config files. Runtime/logger/delegates/registrations remain rooted; map changes do not dispose published hooks.

The concurrent savegame task changed MoatMovePlugin to use Shared.GameplaySessionLifecycle. That user-owned change is preserved; its source links (including GameModeHelper) and installed Steamworks reference were added. Shared/API sources are not modified by the Fast rewrite.

## Verification and remaining acceptance

Tests exercise the actual new route/ownership/pool/cache code, directed BFS reference comparisons, source compilation against installed assemblies, Precise fixtures, native buffers, work/attack/reconstruction/rollback and common distribution for1/100/680 members. The explicit changed-source inventory is FAST_PROVENANCE.json; original extraction hashes remain in SOURCE_PROVENANCE.json. Machine checks cover all33 native function targets and12 observer sites, including the three new entries. Runtime JSON/lifecycle and CRLF checks remain mandatory before the build driver.

Aggregated `stage=fast-performance` logs report queued/completed/pending commands, queries, node expansions, field reuse, oversized routes, retries, topology changes, maximum waiting ticks, synchronous query time and field bytes. Timing measurements never control scheduling. Native command execution and exceptional synchronous searches can still cause tick spikes.

Final verification and installation completed on 2026-09-13. Full runtime/source fixtures, independent route/state/cursor models, explicit provenance and installed RedBird decode contracts passed. The Fast reconstruction publication also checks the shared ground field before consuming a native field populated for another group member; a regression fixture verifies direct ground publication with native mode zero. JSON/lifecycle/CRLF preflight (36 runtime sources) and git diff --check passed. The build.bat /nopause driver was run once, elevated, with exit code zero; it verified matching installed DLL/PDB/manifest hashes and retained the existing Mode = precise config. The runtime build emitted only CS0649 warnings for unused legacy diagnostic counters; version remains 0.1.0. Game acceptance requires separate Precise, Fast and Fast+APIShared runs, including Stop, quick replacement, partial groups, Shift/patrol, work/attacks and saves with pending/empty queues.
