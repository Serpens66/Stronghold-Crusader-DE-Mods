Full command decoding and semantic-database Xrefs show no outside entry into this range's interior. The other consumer calls at `0x1206DF` and `0x120CCD` belong to other command branches and are not hooked; the former has an incoming jump to its interior and is unsuitable for this placement.
- Commands 9, 36 and 38 share the building branch. The diagnostic scopes commands 9/36, so unscoped executions are explicitly reported without inferred ownership. The eligible melee count and editor/building-type gates may bypass the builder and filter entirely; absence of a marker does not prove inaccessible terrain.
- At the observer, EDI is the original 1-based tribe ID, R14D the original 1-based building ID, and the context is `module+0x60AD660`. Compare these with the event frame, current Global-IDs, and the public Extender context address. Context-relative list offset is `0x1B344`, capacity 500, approach-only sentinel.
- The live filter executes exactly once at the unchanged native RSP. The observer preserves volatile GPRs RAX/RCX/RDX/R8-R11, XMM0-5, and flags; Win64 preserves nonvolatile GPRs/XMM6-15. RSP is 16-byte aligned after eight pushes and the native 0x88-byte allocation; the observer uses a separate aligned 0xD0-byte frame and 32-byte callback shadow space. LEA does not clobber flags. The original CMP recomputes the condition immediately before the original JE. No RedBird ContextHook wrapper is involved.
- Installed `X64InlineHook` decodes at least 14 bytes, yielding exactly 17 here. The generator and post-commit check verify the complete span before logical publication. The transaction, handle, receiver and delegate stay statically rooted. Disposal is restricted to an unpublished initialization candidate; map transitions only invalidate logical evidence.
- MoatMove can own the builder/filter function detours; this observer calls their live entry and reads its final output before Vanilla's gate. Script Extender owns the command entry and its Pre/Post events; this observer leaves them intact. The canonical local Fixes clone has no overlapping hooks. Snapshot and live bytes are both checked before installation, rejecting unexpected overlaps.
- `Verify-NativeSearchSpan.ps1` checks installed hash, exact bytes, boundaries, direct incoming branches and both continuations. The retained `.inspect/RaidRetargetEvaluation` harness compiles the actual emitter, prepares the same installed backend on a copied span, decodes the emitted stub, and executes both gate branches on isolated test memory. It also checks observation association and unchanged empty results. These are static/harness checks, not proof of a game callback.
- When updating Native or RedBird, repeat the complete feature and backend audit, database Xrefs, register/stack/flag analysis, live overlap checks and harness. Until verified, disable only the execution observer and retain the existing diagnostic/fix behavior.
- Runtime acceptance requires `RAID_DIAG_SEARCH_HOOK`, `RAID_DIAG_SEARCH_CONFIRMED`, an open positive control, an enclosed negative control, and the uncertain raid armoury sequence without callback errors. `executionEvidenceDrivesFix=False` remains in effect until those controls have been evaluated.
