# In-game acceptance: DrawbridgeDestructionFixTest 0.1.0

The user confirmed a successful editor smoke test on 2026-10-13. Native counters recorded 167 entries and 166 protected decisions, but detailed editor diagnostics were inactive because new editor creation did not arm the session. Full instrumented acceptance remains incomplete. BugfixesAndQoL is unchanged.

1. Start the game with the installed testmod. Confirm DRAWBRIDGE_FIX INSTALLED and READY without INITIALIZATION_FAILED.
2. Create a new editor map, then separately load an existing editor map and test_gates_v2.sav. Confirm diagnosticRevision=2, exactly one MAP per session (source=EditorCreated/EditorLoaded/LoadedSave) and a new RUNTIME_AFTER_STARTUP_CLEANUP marker in each session. Let a normal attacking unit hit a gatehouse with a drawbridge.
3. Confirm HOOK_CONFIRMED with plausible gate/global ID, coordinates and enteredDelta. For nonlethal direct hits, DAMAGE_POST should show positive remaining gate HP and suppressedDelta>0; both bridge identities should remain alive. Check NEXT_TICK and visible bridge presence/movement.
4. Keep attacking until the gatehouse is actually destroyed. The regular Vanilla branch must remove its bridge(s), including tile occupancy and pathfinding. Check destruction and later slot/global-ID observations.
5. Repeat for small/large stone gatehouses, one/two attached bridges, bridge lowered/raised and elevated terrain if available. A gatehouse without a bridge must still take normal damage.
6. Catapult/trebuchet direct bridge hits must retain Vanilla immunity. Projectile/area damage on gatehouses and manual gatehouse demolition must preserve regular removal behavior.
7. For comparison, close the game, set Fix.Enabled=false in BepInEx/config/DrawbridgeDestructionFixTest_Serp.cfg and restart. The early-destruction bug should reproduce, with suppressedDelta=0. Restore true and restart for further testing.

Detailed nonlethal diagnostics are capped at 64 gate damage episodes per map, with 32 additional lethal episodes and at most eight later removal observations per episode. Lethal episodes beyond the initial budget retain their Pre snapshot and log it retrospectively at Post. Once both budgets are exhausted, no building/tile snapshots are captured. Errors are capped at three detailed messages. Native counters remain process-wide internally, but MAP_END reports session-relative entered/suppressed/error deltas, damagePre/Post pairing, gateCaptures, pendingAtEnd and confirmation coverage. Duplicate/replayed starts and stale/duplicate ends are ignored. Each session gets its own hook/tick confirmation marker. Nested callbacks are indicated; counter deltas do not establish exclusive attribution when other callbacks execute between observations. The existing damage publisher does not expose the final damage arguments or native return value. Native ticks stop while paused.

Diagnostic revision 2 uses APIShared's public owner-bound mission lifecycle, including EditorCreated/EditorLoaded and ready-session replay. Footprint geometry is cached by building/global identity, coordinates and size; occupancy/eligibility remain live on every captured hit. Episodes and the two bridge snapshots are value types; no per-hit episode object, snapshot arrays or closure delegates are created. APIShared's existing coupling helper still creates its small result list; its public contract is unchanged. Production observer fixtures exercise session transitions, nested pairing and exhausted budgets; an allocation check covers warmed-up callbacks after both budgets have been consumed. This does not measure FPS or prove allocation-free detailed logging/live geometry refresh.

Initial acceptance is singleplayer. NetworkMode=1 correctly classifies gameplay changes, but this test uses startup BepInEx configuration rather than host synchronization. Multiplayer peers must use the same configuration; multiplayer release requires separate acceptance. No automatic attacks, damage injections, save writes or test-unit spawns are performed.
