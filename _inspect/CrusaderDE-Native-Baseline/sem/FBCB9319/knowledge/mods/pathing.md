# Pathfinding, routes and unit movement [Scope: Mod work, not Vanilla]

What our mods, testmods and external components do with Vanilla routing and movement. Native hash FBCB9319 throughout. Vanilla facts are in [vanilla/pathing.md](../vanilla/pathing.md); native address registers are each mod's `UpdateToNewDLL.md`. Summary state 2026-11-27; statuses carry the date of their evidence. Link texts abbreviate audit file names as in the Vanilla file's [Sources](../vanilla/pathing.md#sources).

## Pathfinding

Owner of unit commands, the route engine, gate routing, Assassin paths, formations, Shift queue and troop movement formerly in BugfixesAndQoL/MoatMove (migration preserved 2026-11-13). Implementation `Pathfinding/src/Engine`, integration `Pathfinding/src/UnitCommands`, native core `Pathfinding/native/PathfindingAnchor.cpp`, contracts [Pathfinding/UpdateToNewDLL.md](../../../../../../Pathfinding/UpdateToNewDLL.md), backlog [Pathfinding/src/TODO.md](../../../../../../Pathfinding/src/TODO.md). ([PM](../PATHFINDING_MIGRATION.md))

- **Compatibility and ownership.** Loads after BugfixesAndQoL and Fixes (soft dependencies); BugfixesAndQoL < 1.0.215 still owns duplicates (startup reports `PATHFINDING_OUTDATED_BUGFIXES`); MoatMove is incompatible. 2026-11-07 coexistence audit: no overlapping spans (`0x119F90` is a BFQoL inline hook but only a Pathfinding call; `0x11FFA7`/`0x123090` call site vs entry; `0x59210`, `0x639C0`, `0x69470` BFQoL interior hooks vs Pathfinding entries); EngineInterface.run keeps the shared bridge first. Dated observation, not a future guarantee.
- **Saves and settings.** Keeps save IDs `BugfixesAndQoL-AssassinClimb` and `BugfixesAndQoL-TroopMovementSync` (intentional `FeatureSaveStates.cs` drift). Legacy settings imported without materializing defaults before the migration journal is persisted; retired BFQoL preset properties stay readable.
- **Simulation contracts.** SimulationRunScope marker on every EngineInterface.run path; gate topology fingerprints are functional; cached answers belong to one audited query pass ([GATEHOUSE_QUERY_PASS.md](../GATEHOUSE_QUERY_PASS.md)). Assassin/formation network handlers use APIShared sender authentication plus receiver ownership checks; packet layout/order fixed; formation sends stay synchronous on the simulation path.
- **Route engine (anchor core).** Native ABIs: `0x0400000F` base (DLL SHA-256 `69393e8e...`), `0x04000010` adds per-node surface class byte (Any, LargeSearch = Vanilla predicate B, RestrictedMovement = R; bits 0x80/0x01/0x02), all searches filter entering edges by class, caches keyed by class revision; `0x04000011` counted workspace budget (one scratch + eight batch banks, 768 MiB = nine 32 MiB quotas + 480 MiB store; 64 MiB 800x800 context returns NoMemory). Managed live audits and a final unit-output guard (bound by exact native output-slot address) recheck entered tiles, including Vanilla and fallback results; unsafe outputs are cleared and returned as failure. Existing saved routes are not repaired. 238,555 native assertions 2026-11-13. ([MSP](../MOVEMENT_SURFACE_PROFILES.md), [vanilla](../vanilla/pathing.md#route-builder-0xf4930))
- **Ground profiles and direction watch.** Ground-only profiles use FastTraversalCache bits 8..15 (BFQoL edge rules without moat height correction; corresponds to `0xDA590`, not `0xDAAC0`'s block test). A chunked watch compares `0x51890D0` with a copy (40,000 tiles per tick, coordinate aliases separately); BFQoL's `0xDAA50` observer then reports `InvalidateFastMoatDirections` instead of a full resweep. Before this fix 4,974 units per run fell back to Vanilla (`pf-iter-7`). Direction-watcher simplification (pf-opt/001) keeps scalar ordered read/shadow/callback semantics only. ([GRB](../GROUND_ROUTE_BUILDERS.md), [ULP](../UNIT_LOAD_PLACEMENT_CONTRACTS.md))
- **Failure proofs (from MoatMove).** `GroundFailureProofs` replays the region gate and direct attempt natively and skips `0xDAAC0/0xDA590` for starts inside a closed failure set (113/113 matched, pf-known-8); `MoatFailureProofs` keeps the stamped component of a failed moat build plus an edge-input hash and skips `0xDAFD0`. ([GRB](../GROUND_ROUTE_BUILDERS.md))
- **Drawbridge planning closure** (since 2026-11-17, moved from EnemyBridgePathTest). Detour after every `0xC4BF0` mode 1: lowered decks in front of a portal are cut from non-deck neighbours, near abutment and aperture edge (via `0xD8CE0` with gate state 0) re-added, all bytes restored before the next call. Detour on `0xF4540`: when the endpoint shares the gate tile's region, its region field points beyond the bridge. Only admitted players reach the deck. Cost ~27 µs per closure window, ~4 µs per portal tick, ~0.1 % of run time at 10,000 units. Accepted in 18 runs (77 deck closures, `.work/t/bridge-accept/`). ([DRC](../DRAWBRIDGE_REGION_CLOSURE.md), [PT](../PORTAL_TABLE.md))
