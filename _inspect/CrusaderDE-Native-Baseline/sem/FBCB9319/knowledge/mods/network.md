## APIShared

### Authenticated Chore channel (opcode 106)
- Reads only a phase-0 opcode-106 pending slot; requires matching source/execution IDs 1..8; rechecks phase, slot, opcode, source, tick and command ID. A process-rooted managed scope around the Script Extender's native-only blob dispatcher binds packet ID/body to that slot before deserialization; validates the 4-byte native length prefix, payload size and completed transfer cursor. Nested calls restore the previous scope; Steam/worker events without the exact thread scope are rejected before native reads. Typed delivery rechecks the captured tuple after consumer validation. SE's opcode-106 handler stays in place. ([PLAYER_CONTROL_CONTEXT.md](../PLAYER_CONTROL_CONTEXT.md#apishared-adapter-mod-integration))
- Sending: SE's public `SendPacketToAllEx2` can re-serialize and fall back to Steam, so APIShared binds SE's internal raw submission method, validates its loaded IL (engine monitor Enter/Exit around the queue call in one try/finally), uses one captured serialization, and rejects the send if bindings were replaced or the native view differs from the real local human. No source field is rewritten. Additive sender checks slot capacity under the engine monitor (local preflight only, not network flow control).
- Status: hash-bound layout checks; no proof of grant validity, compatible peers or stable object ownership.

All four must validate before a lease is available; inactive cell = original loads; partial publication keeps roots with the cell inactive. NativeX64 backend SHA-256 `0843DD4C...AADB0`. No live acceptance. ([PLAYER_CONTROL_CONTEXT.md](../PLAYER_CONTROL_CONTEXT.md#positive-participant-view-integration-boundary-mod-integration))

### Spectator input control
- Installs both input boundaries for this hash only on first consumer registration: RunTick `[0x868F6,0x86900)` Indirect/10 and nested `[0x8D128,0x8D12E)` Indirect/6 (followed by the unchanged store). A clear spectator comparison always follows the original block. `LocalInputControl` owns the actor cell; `PlayerPerspectiveAPI.TrySetSpectatorControl` deselects as the old view, confirms the new view, then publishes the actor, all under the engine monitor. World invalidation resets without commands. Gives full Vanilla input of one player for original offline spectators. Fixtures cover both stub forms and 108 relocation combinations.

Needs a native queue reset/drain proof before retiring control; only non-suspending startup options validated.

## Pathfinding

Extended Shift command queue (`Pathfinding/src/CommandQueue/`; documented in [Findings/QueueTest.md](../../../../../../Findings/QueueTest.md) and `Pathfinding/UpdateToNewDLL.md`; originally in BugfixesAndQoL):
- Hooks: whole-function detours of Chore-17 handler `0x10AE0` and Chore-36 handler `0x12BF0` (verified table entries 17/36/71 at `0x2C7A30`, sizes, tails); whole-function detour of append helper `0x11C3A0` (Chore 71); overlay renderer `0x1222A0`; optional draw-filter `0x417A0`. All hash-bound, fail-closed; failure of the MP marker hooks rolls both back and leaves Chore 71 Vanilla; SP/editor queue paths unaffected.
- MP protocol: during mode-1 serialization of a local Shift command the sender marks Chore 17 move type with bit `0x40` (`0x40/0x41/0xC1`) and Chore 36 commands 4/9/36 with bit `0x80`; every peer consumes marks in mode 0, restores the parameter, enqueues and skips Vanilla. Unmarked 17/36 discard the tribe's managed queue. No opcode 106, no extra packet; reads handler mode `0x85F8FEC` and patrol staging `0x86C1338` (`PatrolInfinite` bypasses queue).
- Queue state: unit-stable cohorts (Unit ID + Global ID), 128-command FIFO, nine-slot visual pages, deterministic branch ordering, tribe isolation via SE `Create`/`UnassignUnit`/`AssignUnit` with rollback; never saved; cleared on map load/unload/restart. Writes attack marker words (unit `+0x68`, building `+0xC2`) after revalidation. `NetworkMode: 1`.
- Regression tests `tests/Issue6.Tests`; in-game looping and real host/client acceptance separate.
