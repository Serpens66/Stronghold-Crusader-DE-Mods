# Script Extender 2.10.1 unit and projectile hook audit

Native input: installed `CrusaderDE.dll`, SHA-256 `FBCB93195FC7EFCA9BDAC5204852EFDD76F9818F59A6711750D77C9CEF2831E2`. Extender input: tag `v2.10.1`, commit `a8ba202f6ec7966bd115b59a6088a0077ce727a0`, tree `1cc818b1b844b5e121054f2dc2edd731206b8c7b`. This record describes this exact pair only. Function names below remain candidate interpretations unless explicitly identified as exports or confirmed in another baseline record.

## Local troop selection

`DLL_TroopSelection` at RVA `0x879A0` is an exported native entry. The existing `MOVE_COMMAND_RELEASE.md` audit follows the tick path through `DLL_RunTick` at `0x86680` and the troop command branch at `0x8C5F0`; selection is consumed locally before commands are sent. The 2.10.1 managed `GamePlayerManagerAPI.GetSelectedChimps()` reads the local `EngineInterface.selectedChimps` array and sizes it with `GetSelectedChimpsCount(GetLocalPlayerId())`. The count API retains its explicit player argument, while the selected-unit array no longer accepts one. Our command/editor callers reject an active player different from the local player; unit IDs in `SelectedUnitInfo` remain game IDs and go directly to ID APIs.

## Target selection and distance

The native function beginning at RVA `0x18E9A0` (VA `0x18018E9A0`, candidate) takes a unit manager base and a unit game ID, uses a `0x490` unit stride, checks attack and target state, maps unit types to projectile range classes, and reads the range table at RVA `0x2DA8F0`. Its target branches validate candidate identity and visibility, compare squared tile distance after world coordinates are shifted by three, and either publish the chosen target/order fields or return without a target. Its existing state-specific fallback resets `+0x9F4` and may hand movement back to RVA `0x196280`. The new Extender loader at `0x18EB20` substitutes a per-type range only when its flag is active. No current Serps mod enables that range override.

The native distance predicate at RVA `0x19B630` (VA `0x18019B630`, candidate) receives manager base, attacker game ID and target game ID in that order. It reads the attacker type from `+0x6E6`, positions from `+0x70E/+0x710`, and, for the two special ranged types, can set attack state `+0x9F4` to `3` and return false when prerequisite state at `+0x9BA` is absent. Otherwise it converts world coordinates to tiles, squares both deltas and compares their sum with the squared type-specific range. The 2.10.0 hook at `0x19B786` replaced that range-table load; the 2.10.1 hotfix adds a capture at `0x19B64E`, preserving the sign-extended attacker type in the unused third Windows x64 shadow-space slot for the later hook. This avoids relying on registers whose values differ at the later site. The source diff does not prove that the external 2.10.0 crash report had this cause.

The projectile initializer at RVA `0xA1DB0` (VA `0x1800A1DB0`, candidate) reads trajectory mode and default speed/angle tables. Its branches write the default to launch speed at projectile offset `+0xAA` or angle at `+0xB0`, then continue initializing projectile state. The Extender inline hook at `0xA1E0E` preserves the original branch sequence and conditionally calculates extended-range launch speed from source unit type, source/target coordinates and elevation difference. The declared minimum hook size is `0x17`; RedBird rounds displacement to complete instructions, so that declaration is not an exact overwritten span.

## Unit updates, interactions and other hooks

The Extender walks thirteen ranged-unit update functions selected from `UnitFunctionsVTable` and hooks compares against unit field `+0x8FE`. It also adds an interaction-range loader near `0x8D769`. The vtable set is separate from the seven wildlife update function entries optionally hooked by the local Fixes clone. Fixes' unit-selection speed patches address field `+0x916`. `ImprovedHunters` has manual-attack sites at `0x18EB36` and `0x18ED96`, after the `0x18EB20` loader; `BugfixesAndQoL` has the attack-pair gate at `0x8D72B` and a peace-time site at `0x8D7C4`, separate from `0x8D769`. The release-wide source fingerprint, classifications and per-site rationale are in `Shared/ScriptExtenderUpdate/2.9.0-2.10.1.release-hooks.json`.

The installed Script Extender has the parameterless selection method and the new projectile interop field. The `GetProjectilesAsSpan()` header-inclusive slot-view bug remains in 2.10.1 source, so the marked local adapter stays. The early crash-handler false-alarm entry has no positive source or runtime fix evidence. `UpdateForScriptExtender` found 365 patterns; the new hotfix AOB matches uniquely at `0x19B64E` for this native hash. It found no changed Ghidra label, prototype, or type input, so the current hash-bound Ghidra exports were retained. Their `0x19B630` record still has candidate confidence, and no new function label was promoted from Extender source comments. No in-game run of these range paths is claimed here.
