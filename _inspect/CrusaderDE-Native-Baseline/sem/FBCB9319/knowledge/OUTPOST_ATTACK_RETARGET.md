# Outpost attacks after a target player is eliminated [Scope: Vanilla]

Native SHA-256 `FBCB93195FC7EFCA9BDAC5204852EFDD76F9818F59A6711750D77C9CEF2831E2`. Static findings for the installed image. See also [Outpost production](OUTPOSTS.md) and [player defeat observation](PLAYER_DEFEAT.md).

- The three Outpost types use `0xABB90`. Group completion calls `0x2E2B0` with the AI manager at `0x404C950`, a one-based tribe slot and the tribe global ID. `0xB8310` can also complete a matching unfinished Arabian or Crusader group when deleting its building. Completion disbands empty groups, excludes humans by the native mode/AI-owner test, and inserts the remaining groups in the first empty or stale slot of a 1000-entry table. Short IDs at AI manager `+0x10CE8` are paired with UInt32 global IDs at `+0x114B8`. The table has no insertion when full.
- `0x2A720(manager, owner, tribeId)` is called only from `0x2E2B0`. It loops over player IDs 1–8 and rejects the owner's team and candidates for which `0x187E60` finds no valid Lord. AIC `who_to_pick_on` drives score comparisons, including distance from the owner's Keep door, candidate resources and lobby participation. The distance helper `0x79C0` exposes the larger of the two absolute coordinate deltas in the scratch field read by the selector. The fallback tries the closest valid opposing player, and native mode 0 can store player 1 if there is no candidate. Other modes can leave the target field unchanged. The selected player is written as an Int16 at `0x7CC6D6A+tribeId*0x688`.
- The group loop `0x30B10` calls `0x30620` only for nonzero group IDs whose global ID still matches. It is reached from `0x2AE40` and the `0x30610` mode-0 path from `0xCDE60`, at native phase 10. `0x30620` first checks aggregate unit states with `0x2DC30`. At `0x30682` it reads the previously selected player. The function can then search for nearby target-player defenses and dispatch command 7 or 35, or select a building (`0xCE570`) and issue command 9 with the building ID and global ID. Some group roles instead derive an approach through `0xDA020`, then test the region route via `0x3E650`. Fallbacks use the target player's stored Keep-door tile and `0x11DD10` for movement where the Vanilla checks allow it. There is no repeat of `0x2A720` in this update. The cached building pair is at tribe manager `+0x64C/+0x650`, relative to the indexed slot. The queue and tribe storage are serialized by the native paths near `0x15A50` and save stage `0x39`.
- `0x1D160` can mark a player out of active play before the match ends. The official WinLoss word at `0x379D014+playerId*0x583C` can remain None after a mid-match death. The player manager anchor at `0xC1CF6` resolves `0x366C210`, so the first player word also follows from `0x366C210+0x1343FC+0x2244`. The Extender calls the separate early player field `r_IsPaused`. Its native mode-dependent writers are not a universal defeat test.
- The selector's own Lord check is authoritative for choosing its candidates. `0x187E60` reads the signed unit slot from `0x3A0F9F0+playerId*2` and validates the Global ID from `0x3A0FA04+playerId*4`, the alive word and the death word. These fields at `+0x6F0/+0x6E4/+0x8F8` are relative to `0x67E8400+unitId*0x490`. The native unit pass `0x182B00` clears and rebuilds the lookup table from Lord units. A slot can therefore disappear after removal, and a newly initialized or loaded table can be empty before the first rebuild. A zero target field is still Vanilla's unassigned value, distinct from an assigned opponent losing their Lord.
