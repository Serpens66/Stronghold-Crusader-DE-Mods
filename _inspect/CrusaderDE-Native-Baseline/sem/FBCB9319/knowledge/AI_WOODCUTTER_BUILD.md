# AI woodcutter construction gate

Native SHA-256: `FBCB93195FC7EFCA9BDAC5204852EFDD76F9818F59A6711750D77C9CEF2831E2`. Evidence: installed `CrusaderDE.dll`, direct Rizin disassembly, and `exports/semantic-decompiled-functions.c` plus `exports/semantic-functions.jsonl` for RVAs `0x51540`, `0x58020`, `0x58950`, `0x58BE0`, and `0xC3BF0`. The 29 September 2026 re-audit corrected the earlier conflation of `0x58950` and `0x58BE0`.

- `0x51540` checks the woodcutter census and calls `0x58020` at VA `0x180051587`, then `0x58950` at `0x1800515CD`. It calls `0xC3BF0` at `0x1800515FF` with player ID, mapper index 3, and coarse result coordinates multiplied by five. Only a nonzero route return reaches `0x6D580` at `0x180051670`.
- `0x58020` selects a coarse wood cell from the live economy grid using the candidate resource byte at cell offset `+0x03` (`state+0x5B837`) and score `resource*5-depth*3`, with additional cell flags and cooldown gates. Its raw function hash is `ECBC0954129AF88CEAC0E0AF0AFBA1558D228DEF1BD9C9BD99DA6E9314447800`.
- `0x58950` (656 bytes; raw hash `311F4EA24FA4B28F28705718F1657C164A136EA4D844B4C5CE7DD7BE0F8E0F97`) searches the 160-by-160 coarse grid and accepts a nearby cell when the relevant bytes at `state+0x5B834 + (x*160+y)*0x30` satisfy its coarse flags: offsets `0`, `3`, `4`, `10`, `11`, `12`, and `15`. It stores the result at `state+0x1B983C/0x1B9840`. Its function metadata has no callees and no PCL-grid data reference; the disassembly confirms no route or fine-tile placement call in this function. It can therefore select an anchor whose PCL is zero.
- `0x58BE0` is a distinct nearby-search function (937 bytes; raw hash `5CE7CFA2EF0439AD7788933A22050235C650244F54973158CFD3C97D55031B68`). It checks a 3-by-3 native placement grid at `0x4C559B0`, reads PCLs at `0x50EC690`, and calls `0xE2610`. The woodcutter call at `0x1800515CD` does not target this function. Never transfer its conditions to `0x58950` without an independently verified call edge.
- `0xC3BF0` (133 bytes; raw SHA-256 `1AC2D046356187774EE0EF0C7F782C59B3E416BAEDDBD463305304CF709EB0B0`) compares the player's keep-tile path component with the target tile's component. Its source tile index comes from `0x379AFB0 + playerId * 0x583C`, its target tile from the row lookup at `0x402FF2C`, and both components from the 320,800-entry grid at `0x50EC690`. When the route check is needed, it calls `0xE2610` with mode 0. A zero return rejects construction; a nonzero return allows the caller to proceed.
- Only on a nonzero route result does `0x51540` call building construction at `0x6D580`. The installed Script Extender already detours `0x6D580` and exposes the pre/post `OnBuildStructure` event. Its post event does not carry the original return value. The lower-level `OnBuildingSpawn` event does carry its post return value.
- The `0xC3BF0` entry begins `48 83 EC 38 49 63 C0`: two complete straight-line instructions spanning seven bytes. The installed RedBird NativeX64 indirect-detour backend must confirm this displacement before an observation hook is published.
- The map coordinates used by `0xC3BF0` belong to an 800-by-800 raster; the playable diamond is narrower, and the packed PCL grid still has exactly 320,800 entries. A target Y value above 399 is valid (the Canari observation used Y=485). Diagnostic readers must validate the coordinate before using the row table and then validate the packed tile ID against the PCL span.
- `0xE2610` returns zero immediately when either component is zero. Otherwise its mode-0 graph search accepts records 1 through 199 only when `r_IsActive == 1`, `r_IsEnabledOrOpen != 0`, the connection class is not ladder climb (class 1), and either the player's and record owner's 32-bit access values match at RVA `0x37EDF3C + id*4` or the record's building gate flag is nonzero at RVA `0x64CCED2 + buildingId*0x32C`. The latter access is 16-bit. This is the observed native filter; record layout is `PathConnectionRecord` size `0x204`, rooted at pathfinding context offset `0x2024`.
- The 29 September 2026 Canari save run logged eight player-6 wood attempts with nearby result `(69,97)`, target tile `(345,485)`, source PCL 3, target PCL 0, and `0xC3BF0` return 0; no `0x6D580` build event or hut spawn followed. A subsequent run sampled direct native and Script Extender PCL views before and after `0x58950`: both were zero at that anchor and unchanged during the search. Only the northwest tile of the measured 3-by-3 footprint had PCL zero; the other eight had PCL 3. The later run's route observer did not install, so its seven attempts do not independently reconfirm the route return. Neither run established the tile's raw terrain or wall properties.

## Coarse-cell and placement follow-up, 29 September 2026

Installed native SHA-256 remains `FBCB93195FC7EFCA9BDAC5204852EFDD76F9818F59A6711750D77C9CEF2831E2`. The direct source chain is `0x50720` (coarse rebuild), `0x58020` (wood resource origin), `0x58950` (nearby coarse search), `0xC3BF0` (route), `0x6D580` (construction), `0x77E60` (placement), and `0x69850`/`0x619C0` (footprint offsets). The Script Extender's `GameBuildingManagerAPI.CreatePrefab` calls its installed `0x6D580` detour and can reproduce the final native placement in an explicitly disposable save.

- `0x50720` mode 1 first initializes the 160-by-160 coarse map, obtains the reference PCL from `0x572B0` into state `+0x5B504`, then walks the 320,800 packed tiles. For every current PCL unequal to that reference it increments the coarse cell byte at `+0x5B834` (sample offset 0). Tile logic, structure IDs, height, resource and other layers feed the other coarse bytes. Mode 0 resets/ages counters. Confidence: high for the branches and referenced layers; the reason why a particular save has a stale counter is not established by this static path.
- A follow-up audit of `0x50720` at installed hash `FBCB9319...2831E2` found three direct call sites at RVAs `0x71A06`, `0x84D1E`, and `0x96D49` for mode 1, and a mode-0 call at `0x575A4`. Mode 0 loops over packed tiles to refresh selected resource/obstruction counters but does not write the foreign-PCL byte at `state+0x5B834`; its existing value survives that path. Mode 1 writes that byte from the PCL grid after initialization. This establishes an update asymmetry, not when the Canari cell first became inconsistent. The tree-weight byte is derived by different flag/structure branches, so a tree flag on an apple-farm tile alone does not imply that its stored tree weight should be positive.
- `0x58950` reads the selected coarse cell at state `+0x5B834 + (x*160+y)*0x30`; after the visitation and traversal gate, its acceptance requires bytes `+10,+11,+12,+15,+3` equal zero, signed byte `+4` below one, and byte `+0` equal zero. It returns the first accepted BFS neighbor without a fine-tile construction check. These offsets respectively represent height-range rejection, structure/reservation, outside usable map, impassable edge, tree weight, stone count, and foreign PCL count in the current Script Extender `AivCoarseCell`. The exact BFS visit order is separate from candidate eligibility. Confidence: high for the branch and offsets.
- `0x51540` passes `(coarseX*5,coarseY*5)` unchanged both to the route check and to `0x6D580` with mapper `0x33`, scale from `0x6A190`, variant `0x0F`, and free flag zero. `0x619C0` initializes scale-3 footprint entries as offsets `0..2` in both axes; `0x69850` supplies them to construction. Thus `(345,485)` is the footprint origin and a tile in the hut footprint, not a separately derived entrance tile. Confidence: high for origin and offset table, medium for unobserved access orientation.
- `0x6D580` calls `0x77E60`, returns when placement-rejected state at tile-manager `+0x204E6FC` is nonzero, otherwise iterates the footprint, mutates tile layers and dispatches to type-specific construction. `0x77E60` has a large mapper-specific jump table and repeated `0x69850`/`0x7B060` tile validation branches; the existing decompiler export exceeds its flow limit. A footprint that appears clear from a few flags is therefore not an authoritative placement success. The diagnostic's single exact-parameter `CreatePrefab` attempt in a named save copy records the actual result and any spawn/access tile. Confidence: high for the terminal rejection and build consequence, explicitly unresolved for a purely static prediction of every placement subcondition.
