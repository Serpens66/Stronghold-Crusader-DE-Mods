# HUD, rendering, minimap, markers, input and unit commands [Scope: Vanilla]

Native hash FBCB9319 (full hash in ../../../../CURRENT.json). Summary state 2026-11-27. Check the installed DLL hash per CURRENT.md before using any address. Evidence links point to the audit documents; they stay authoritative.

Managed facts refer to the real `Assembly-CSharp.dll` SHA-256 `BC8B6A39...` (full hash in the audit documents). All RVAs are for the FBCB9319 image; VA = 0x180000000 + RVA.

## Overview

- Native code does not draw. Every tick `DLL_RunTick` (0x86680) runs input/command decision, the visible-map renderer and the minimap pass, and fills caller-owned output buffers; the managed side turns them into Unity sprites, tilemaps and Noesis HUD state.
- Order inside `DLL_RunTick`: command decision 0x8C5F0 (call at 0x86920) -> visible renderer 0x41D60 (call at 0x86A68; it ends with draw-list reset 0x41D10) -> dialogue 0x41C0, native sound handling -> minimap pass 0xF5A40 (call at 0x86B9B, also when paused) -> PlayState/selection export 0x19D960. The simulation body 0xCDE60 is gated by pause; presentation passes are not.
- Output records are 21 signed shorts (42 bytes). `GameMap.processTestMap` consumes them in order (sprites/"pixies", unit "chimps", building animations, tile packets, speech, video, text); `GameData.setGameState` and `FatControler.NoesisGUIUpdateChecksInGame` then update the HUD.
- Managed path: `EngineInterface.run` (simulation thread `Stronghold1Engine`, holds private static `EngineInterface.threadLock` for the whole tick) -> `preDLLCallActions` -> `DLL_RunTick` -> `CopyPlayStateStruct` -> `MemoryBuffers` (ring of 6) -> `Director.Update` (main thread, up to 3 buffers per frame) -> `processTestMap` -> `setGameState` -> GUI checks.
- Input: `DLL_TroopSelection` (0x879A0) stores mouse state; 0x8B7E0 and the cursor resolver 0x79B90 classify the cursor target; dispatcher 0x8C5F0 turns a release edge into a command (ground move via stager 0x195E30 and Chore 17).
- HUD and side-HUD visibility, patrol tooltip, troop-action panels and calendar date are pure managed/XAML logic.
- Engine: the installed Windows Player logged Unity 2021.3.45f2 (revision 88f88f591b2e) on Direct3D 11 (2026-11-23); a mod shader bundle loaded with `AssetBundle.LoadFromFile` rendered in SHCDE's Universal 2D pass ([UNITY_ASSET_PIPELINE.md](../UNITY_ASSET_PIPELINE.md)).

### Tick, pause and managed bridge
- `DLL_GameAction` 0x418 writes signed `value` to the pause global and returns 0; `structureID`/`value2` unused. Managed `GameAction` return is not a pause success signal. [confirmed, export] ([AUTOMATION_PAUSE_ZOOM.md](../AUTOMATION_PAUSE_ZOOM.md))
- In 0xCDE60 time/update work requires pause == 0; the simulation body requires skip byte == 0 and pause < 1; a negative pause normalizes to 0; positive pause skips the body but not preparation/presentation. Network loading/acknowledgement states can independently block progress. [confirmed, static] ([AUTOMATION_PAUSE_ZOOM.md](../AUTOMATION_PAUSE_ZOOM.md))
- Named-global pause readers (complete for named references, not aliases): 0x2230, 0x25E0, 0x87D0, 0x71670, 0x81870, 0x87D10, 0x89D10, 0x89F40, 0x8BD60, 0x90830, 0x90CD0, 0xCDE60 (3x), 0x19D960. None is a second public pause command. [confirmed, static] ([AUTOMATION_PAUSE_ZOOM.md](../AUTOMATION_PAUSE_ZOOM.md))
- `lastGameState.game_paused` is a copy made by 0x19D960 and can lag a direct native read. Read 0/1 only in a ready gameplay session. [confirmed, static] ([AUTOMATION_PAUSE_ZOOM.md](../AUTOMATION_PAUSE_ZOOM.md))
- Vanilla non-MP pause key sends Game_Paused (1,1) or (0,0). `Director.Paused` is a separate managed flag; `SetPausedState(true)` refuses MP and false does not clear the native pause. [confirmed, static] ([AUTOMATION_PAUSE_ZOOM.md](../AUTOMATION_PAUSE_ZOOM.md))
- `PerfectPixelWithZoom.adjustZoom(float,bool)`: positive zooms in, clamps/wraps step, interpolates in Unity time, no pause check (pause gates are in KeyManager/CameraControls2D). `SetZoomImmediate(float)` sets scale without syncing `zoomPos` or cancelling interpolation. [confirmed, static] ([AUTOMATION_PAUSE_ZOOM.md](../AUTOMATION_PAUSE_ZOOM.md))
- `EngineInterface.run(Boolean)`: free buffer at IL 0006 (returns 0 before locking if none), Monitor.Enter 001D, `DLL_RunTick` 0222, returnBuffer 0282, Monitor.Exit 0291 in one finally. A run call is not proof of advanced game time. [confirmed, static] ([ENGINE_PRESENTATION_BRIDGE.md](../ENGINE_PRESENTATION_BRIDGE.md))
- `Director.runSimTickTest` runs `run` on thread `Stronghold1Engine`, queued by a `System.Threading.Timer` at game speed. The main thread blocks on `threadLock` only for discrete inputs (KeyManager hotkeys, HUD buttons via `GameAction`); `TroopSelection` and building placement run in `preDLLCallActions` on the engine thread. [confirmed, static] ([MOVE_COMMAND_RELEASE.md](../MOVE_COMMAND_RELEASE.md))
- Director runs GUI checks for rendered buffers and at a 100 ms fallback interval while simulation runs. Script Extender `OnTick` does not fire while paused. [confirmed, static] ([HUD_PRESENTATION.md](../HUD_PRESENTATION.md), [NOTIFICATION_LAST_FRAME.md](../NOTIFICATION_LAST_FRAME.md))
- Paused ticks still cost 5.1-6.5 ms vs 6.6-6.9 ms running (40 ticks/s, `test_dustyFPS2.sav`); presentation passes 0xF5A40/0x41D60 dominate. [runtime] ([RADAR_PASS_F5A40.md](../RADAR_PASS_F5A40.md))
