## Overview

- All AI runs from `0x57330` (per-player scheduler, only when global `0x8574B90` != 0) into `0x2AE40`, which uses rotating slot counters (`+2D078/+2D07C/+2D080`) to run per-player passes: market/production, recruitment, castle-defense controllers, raid update `0x3E200`, siege controller `0x3C2E0`, strategy `0x2F080` and target choice `0x2F670`.
- Construction: `0x539B0` is the five-phase economy/AIV cycle. With a selected AIV it runs prepared frames through `0x51790` (frame executor) → cleanup `0x5CD90` → access check `0xC3BF0` → constructor dispatcher `0x6D580` → placement validator `0x77E60`/`0x7B060`. Selection state 0 uses procedural construction `0x52270`. Executor state BYTE0/4 returns before all geometry writes; counted inactive zero-mapper holes are legitimate, including a Keep frame consumed by preparation. Restricted attempts other than hovels, cooldown-only frames (including Built stair1..6 with a nonzero delay) and ordinary Built frames with a matching anchor building can also return before geometry. Eligible frames may still clean terrain before a later placement failure. ([cooldown and matching-anchor boundaries](../AIV_BUILD_RANGE.md#executor-cooldown-and-existing-building-returns-27-november-2026-vanilla-facts)) `[confirmed, static]` ([exact executor boundary](../AIV_BUILD_RANGE.md#executor-inactive-frame-geometry-boundary-27-november-2026-vanilla-facts))
- Additional executor boundaries: Built3 with the signed player counter below120 and the signed manager counter below20 return before geometry. Ordinary Built cooldown also depends on two player flags; missing anchors can rebuild. All three ordered-field loops restart at index0, so there is no general saved-progress tail to observe. These are static native facts, without a measured frequency or a new Runtime filter. `[confirmed, static]` ([exact branches and integration limits](../AIV_BUILD_RANGE.md#additional-executor-admission-boundaries-27-november-2026-vanilla-facts))
- Game start: `0x94350` removes serialized starts, selects AIVs (`0x54F60` auto / `0x54DE0` fixed / fit scan `0x57080`), prepares the plan (`0x53D00`), builds the compound Keep (`0x6D580` → `0x74DA0`) and optionally executes the completed castle (`0x55F50`).
- Economy: market controller `0x3F270` alternates purchase `0x3EC90` (consumes a per-good Pending cell) and sale `0x3EE10`; transactions `0x29650` buy / `0x29700` sell; prices `0xCEB10/0xCEB90`. Site searches use a 160x160 coarse grid (cell 5x5 tiles, stride 0x30) maintained by `0x50720`.
- Military: unit role `GameUnit+0x426` (1..22) maps to fixed player tribe storage slots; classifiers `291F0/292F0/29360/29430/294B0/29520`; tribe allocation `0x119D60`, membership `0x11D370`; group movement `0x11B520`, targeted group order `0x11E960`, strategic per-unit dispatch `0x122B40`, single-unit route `0x196280`.
- Sieges: state machine 0..9 in `0x3C2E0` (player `+0x2BA4`), start test `0x2FEF0`, planner `0x2D250`/`0x2C480`/`0x3BD50`, keep-access predicates `0xCF360/0xCF400`. Raids: six harassment storage slots 180..185 handled by `0x3E200` with candidate list `0x29190` and priority selector `0x2C620`.
- Outposts (building types 2/106/107) all dispatch to `0xABB90`; finished AI groups are queued by `0x2E2B0` and get an enemy Lord from `0x2A720`.
