# Keep campground ground: confirmed observation path

Native DLL SHA-256: `FBCB93195FC7EFCA9BDAC5204852EFDD76F9818F59A6711750D77C9CEF2831E2`.
Managed Assembly-CSharp SHA-256: `BC8B6A395F01D48557DB413600C8DD8D1FDFD3ABDF97BFBBB68A3C56B04FD789`.
These hashes were checked against the installed game on 2026-09-26.

- RVA `0x5BC70` (candidate reset/unload function) initializes 320,800 GFX cells at tile-manager offset `0x140900`, then calls `0x65830` and `0x650C0`. The former has extensive terrain/structure-dependent GFX writes; the latter fills eligible zero-GFX cells under logic and terrain conditions. Calling the reset function a new-map initializer would be incorrect.
- RVA `0xB47E0` (candidate building allocator, uniquely matched by the installed Script Extender building-spawn AOB) receives owner, coordinates, structure type, scale and variation, validates the map coordinate, allocates a 1-based building ID and record, and has explicit branches for Keep types `0x28..0x2C` and Campground `0x37`. Its wrapper raises `OnBuildingSpawn` before and after the original call. These values match the installed `SHCDESE.Interop.eStructs` enum and the local Extender source.
- RVA `0x6E620` (`c_game_update_visual_resourcetile`, confirmed by installed Extender AOB) writes packed file/image values to GFX offset `0x140900`; selected branches also write Alpha-GFX offset `0x279D80`. It has a specific case for Keep One (`0x28`), while other structure types, including Campground (`0x37`), can flow through the generic case. More exact campfire sprite IDs require runtime observation.
- In the matching managed assembly, `GameMap.processTestMap` consumes the native render records and calls `SpriteMapping.setGenericBuildingTileGraphic`; the result is `GameMapTile.tileImage`. `gameTile.GetTileData` uses that sprite for z=0. There is no separate managed original-ground sprite at that stage.

For a read-only diagnosis, `OnBuildingSpawn(Pre)` is the earliest target-specific public event. Its GFX sample can already be changed by earlier parent logic; it must be marked first observed, not automatically original terrain. Subsequent Post, tick, render, and save-load samples identify the first *observed* change without assuming the still-unverified exact campfire writer or tile footprint.

## Confirmed store branch for the preserve test

An instruction-level audit of the same installed DLL found the generic building GFX store at RVA `0x6F0A0` (8 bytes) and its immediately following record read at `0x6F0A8` (8 bytes). The latter feeds an AlphaGFX calculation and store at `0x6F0D0`; RVA `0x6F0D8` is the shared loop tail. The record type word at image-relative `0x64CCCDE` can discriminate campground `0x37`. The local `KeepCampfireGroundPreserveTest` uses a 16-byte `X64InlineHook` at the GFX store and runs both original displaced instructions for other records. The branch leaves structure and logic work before the store untouched. Demolition goes through `0xB8310 -> 0x61FC0 -> 0x628F0`, clears structure occupancy and schedules graphics refresh; its visible behavior still requires in-game testing.

## 2026-09-26 sprite and terrain follow-up

- The observed campground occupies 49 structure cells, but its initial Vanilla file-6 GFX changes cover a 6x6 block (36 cells), relative positions `(0..5, 0..5)` from the reported origin. The file-6 indices in this block are `0x18..0x45` in a diamond-oriented arrangement. `SpriteMapping` passes these indices unchanged to `spriteLoader`'s `tile_buildings1 NNN` sprites. Exported installed sprites in that range show the dirt/stone floor and dark fireplace, not a full cauldron or flame. Managed enum values `FX_CAULDRON=61`, `FX_STIR=62`, `FX_CAMPFIRE=63` identify separate effects; their exact initial rendering dependency is not yet established.
- The five adjacent floor images `0x29,0x2A,0x30,0x36,0x37` formed an incomplete stone ring in the first game test. The adjoining `0x24,0x2F,0x31,0x3C` complete a contiguous 3x3 centre and are the next test candidate. A Vanilla screenshot taken before peasants arrived confirms that cauldron and flames are absent at that stage even without the mod; only the round stone fireplace needs to appear immediately.
- `0x65830` contains multiple GFX writes and at least three confirmed GFX-zeroing instructions, including `0x68640`, `0x68FBA`, and `0x6901F`; `0x650C0` later creates macro-land sprites for eligible zero-GFX cells, with many possible write branches. Observed free-cell outputs such as `0x00370303` are compatible with its macro-land ranges. The individual clear/write instruction responsible for the Keep's initial free-cell changes has not been established, so a narrow suppression hook is not justified yet.
- The Keep creation path at `0x74DA0` places its main building and the campground (`0x37`), marks the footprint through `0x69850`/`0x6FE90` and `0x5D740`, and invokes `0x6CDD0` plus `0x725E0` for visual/path updates. The main simulation tick at `0xCDE60` calls `0x65830` and then `0x650C0` in that order. `0x650C0` only chooses a macro-land GFX sprite where the current GFX cell is zero and the eligible logic flag is set. This establishes the phase order, but does not identify which of the many `0x65830` stores prepares each free grass cell.
- The 2026-09-26 nine-sprite field test left all 49 campground structure cells occupied, retained the original GFX/AlphaGFX on 40 cells, and passed through nine file-6 graphics. In the same first visual tick, a 21x21 Keep sample recorded 266 graphic changes, including 196 cells that remained structure-free. The nine central Vanilla sprites each contain visible fireplace pixels together with dirt; selecting other whole sprites cannot translate those pixels independently of their fixed world cells.
